# SDD 4.2 - Draft Pipeline

## 1.0 Idea

Once the LLM generates a response (from Task 4.1), we need to display it to the user as a draft. The user can then review, edit, and send this draft. This completes the "human-in-the-loop" workflow.

## 2.0 Structured spec

### 2.1 Scope

- [ ] (2.1.1) **Receive Draft**:
    - Handle the `LlmResponse` from the provider (or the stub from 4.1).
    - Update the UI to show this draft.
- [ ] (2.1.2) **Display Draft**:
    - Use the existing `DraftModal` (or a dedicated pane) to show the generated text.
    - Title should be "LLM Draft".
    - Focus should switch to this modal/pane.
- [ ] (2.1.3) **Edit Draft**:
    - The draft area must be editable (it's an input field).
    - Reuse `InputState` logic if possible, or extend `DraftModalState` to support editing.
- [ ] (2.1.4) **Send Action**:
    - `Enter` (or `Ctrl+Enter`) in the draft modal sends the text to the *current* chat.
    - This reuses the `SendPipeline` from Task 2.3.
- [ ] (2.1.5) **Discard Action**:
    - `Esc` closes the modal without sending.

### 2.2 UI Changes

- **Draft Modal**:
    - Ensure it's editable. Currently `Paragraph` widget is read-only.
    - We might need to switch `DraftModalState` to use `InputState` or a `TextArea` widget if `Paragraph` isn't sufficient for editing (or simple `InputState` with multiline support if we have it, otherwise standard single line might be limiting for LLM drafts).
    - *Decision*: For MVP, let's try to stick to `InputState` but handle multiline if the TUI input handling supports it. If not, we might stick to single-line or implement basic multiline editing.
    - *Refinement*: Our `InputState` is likely single-line. TUI crates like `tui-textarea` exist, but let's see if we can do simple multiline editing or just reuse the Composer pane logic (which is likely single line too?).
    - *Alternative*: Put the draft into the **Composer** pane instead of a modal. This is more natural. The user sees the draft in their normal typing area.
    - *Decision*: **Populate Composer**. This simplifies everything. No new modal needed for editing.
    - *Flow*: Export -> Processing... -> Composer filled with Draft -> User edits -> User sends.

### 2.3 Data Model

- **UiAction::UpdateComposer**: New action to replace composer text.
