# SDD 4.5 - LM Studio Support

## 1.0 Idea

Enable users to use local LLM runners like LM Studio or Ollama as the backend for
the "Export to LLM" feature. This replaces the hardcoded OpenAI-only (or mock)
assumption with a configurable provider system that supports custom Base URLs,
allowing usage of OpenAI-compatible local APIs.

## 2.0 Structured spec

### 2.1 Scope

- [x] (2.1.1) **Configuration**:
  - Add `[llm]` section updates to `app.toml`.
  - Support `provider` selection ("lm_studio", "openai", "mock").
  - Support `base_url` configuration for local providers.
  - Support `model` selection.
- [x] (2.1.2) **Provider Logic**:
  - Refactor `OpenAiProvider` to support a custom `base_url` instead of
    hardcoded `https://api.openai.com/v1`.
  - Ensure compatibility with `async-openai` crate or raw reqwest implementation
    if needed (decided on `async-openai` with config overrides).
- [x] (2.1.3) **TUI Integration**:
  - Update `main.rs` to initialize the correct provider based on config.
  - Update `tui.rs` to assume a generic `LlmProvider` trait object is passed
    down, removing any hardcoded provider logic.

### 2.2 Data Model

- **AppConfig**:
  - Added `LlmConfig` struct.
  - Added `LmStudioConfig` struct.
  - Added `OpenAiConfig` struct (for future full OpenAI support).

## 3.0 Implementation plan

- [x] (3.1.1) **Dependencies**:
  - Add `async-openai` for robust client handling (initially tried raw reqwest,
    but async-openai is cleaner).
- [x] (3.1.2) **Refactor Config**:
  - Update `app/src/config.rs` to parse new TOML structure.
  - Update `app/config/app.toml` default values.
- [x] (3.1.3) **Refactor Provider**:
  - Update `llm/src/openai.rs` to take `base_url` in constructor.
  - Use `async_openai::config::OpenAIConfig` to set the custom URL.
- [x] (3.1.4) **Wiring**:
  - In `app/src/main.rs`, switch on `config.llm.provider`.
  - Instantiate `OpenAiProvider` with LM Studio settings if selected.

## 4.0 Test plan

- [x] (4.1.1) **Compiles**: Ensure new config structures don't break existing
      builds.
- [x] (4.1.2) **Config Loading**: Verify `app.toml` is read correctly (via
      `cargo test` in `config.rs`).
- [x] (4.1.3) **Manual Verification**:
  - Start LM Studio server.
  - Run app.
  - Select messages -> Export to LLM.
  - Verify draft appears in composer (generated by local model).
