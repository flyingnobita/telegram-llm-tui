# SDD 4.1 - Export Pipeline

## 1.0 Idea

Allow users to select a range of messages from the current chat, format them into a structured transcript (including author names and timestamps), and prepare them for processing by an LLM provider. This is the first step in the "LLM workflow".

## 2.0 Structured spec

### 2.1 Scope

- [x] (2.1.1) **Message Selection**:
  - Users can toggle selection of individual messages (already implemented in TUI).
  - Provide a way to "select all in view" or "select range" (nice to have, but manual toggle is MVP). -> Implemented "Select all in view" with `Ctrl+a`.
- [x] (2.1.2) **Export Action**:
  - A key binding (e.g., `Ctrl+e` or via Command Palette) triggers the export of selected messages.
  - If no messages are selected, warn or select the last N messages (optional default).
- [x] (2.1.3) **Transcript Formatting**:
  - Convert selected `CachedMessage`s into a clear text format.
  - Format: `[YYYY-MM-DD HH:MM] Author: Message content`.
  - Handle replies (maybe indicate "Replying to...") if possible, but simple linear log is MVP.
- [x] (2.1.4) **Prompt Selection (Stub)**:
  - For this task, we just need to bundle the transcript with a "default" system prompt or user instruction.
  - We won't implement the full "Prompt Kit" (4.3) yet, just a hardcoded or simple input for the prompt.
- [x] (2.1.5) **Provider Interface (Stub)**:
  - Define a trait `LlmProvider` in the `llm` crate.
  - Implement a `MockProvider` or `OpenAIProvider` (basic) that takes the transcript + prompt and returns a `Future<Output = String>`.
  - _Note_: Task 4.2 handles the _result_ (Draft Pipeline). This task stops at _sending_ or _preparing_ the request.

### 2.2 UI Changes

- [x] **Command Palette**: Add "Export Selected to LLM" command.
- [x] **Loading State**: Show a "Processing..." indicator or log message when export starts.

### 2.3 Data Model

- [x] **LlmRequest**: Struct containing `transcript: String`, `system_prompt: String`, `user_instruction: String`.
- [x] **LlmResponse**: Struct containing `text: String`.

## 3.0 Implementation plan

- [x] (3.1.1) **LLM Crate**: Define `LlmProvider` trait and `LlmRequest`/`LlmResponse` structs in `llm/src/lib.rs`.
- [x] (3.1.2) **Transcript Formatter**: Implement a function in `core` (or `app` if it depends on UI state) to format `Vec<CachedMessage>` into a String.
- [x] (3.1.3) **Wiring**:
  - In `app/src/tui.rs`: Handle `Ctrl+e` (or similar).
  - Collect selected message IDs from `UiState`.
  - Retrieve full message objects from `CacheManager` (need to expose `get_messages_by_ids`).
  - Format transcript.
  - Trigger an async task to "send" (print to log for now, or call the mock provider).

## 4.0 Test plan

- [x] (4.1.1) **Unit Tests**:
  - `transcript_formatter` correctly formats a list of messages.
  - `LlmProvider` trait allows mocking.
- [x] (4.1.2) **Integration**:
  - Select messages -> Trigger Export -> Verify formatted transcript appears in logs (or mock output).
