# SDD 2.5 - Message history bootstrap

## 1.0 Idea

Fetch recent message history for all chats at startup so the UI can render
immediately and the cache persists useful context without waiting for new
updates.

## 2.0 Structured spec

### 2.1 Scope

- [x] (2.1.1) Fetch recent message history for all dialogs at startup.
- [x] (2.1.2) Default to 100 messages per chat; make this configurable.
- [x] (2.1.3) Store fetched messages in the cache and persist them to sqlite.
- [x] (2.1.4) Preserve message ordering oldest to newest in the cache.
- [x] (2.1.5) Run history sync in the background so TUI startup is not blocked.

### 2.2 Out of scope

- [ ] (2.2.1) Full backfill beyond the configured per-chat limit.
- [ ] (2.2.2) Media downloads or rich message rendering.

### 2.3 Data flow

- [x] (2.3.1) Use the dialog list to resolve peer references for history fetch.
- [x] (2.3.2) Map raw Telegram messages to MessageNew cache entries.

### 2.4 Configuration

- [x] (2.4.1) Add `history_per_chat` under `[telegram]` in `app/config/app.toml`.
- [x] (2.4.2) Cap history fetch by cache max messages per chat.

### 2.5 Logging

- [x] (2.5.1) Log overall dialog and message counts plus per-chat failures.
- [x] (2.5.2) Avoid logging message bodies during history sync.

## 3.0 Implementation plan

- [x] (3.1.1) Add a dialog snapshot type that includes a peer reference.
- [x] (3.1.2) Add a core helper to fetch recent messages for a peer.
- [x] (3.1.3) Wire startup sync to fetch dialogs, cache summaries, and history.
- [x] (3.1.4) Add config parsing and defaults for history fetch.
