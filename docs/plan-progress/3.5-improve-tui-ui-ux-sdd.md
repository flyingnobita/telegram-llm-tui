# SDD 3.5 - Improve TUI UI/UX (Lazygit-like)

## 1.0 Idea

Adopts a `lazygit`-inspired UI/UX philosophy: clean, panel-based layout, consistent keybindings, explicit focus management, and discoverable key hints at the bottom. The goal is to make the application navigable and usable primarily via keyboard with immediate visual feedback.

## 2.0 Structured spec

### 2.1 Scope

- [ ] (2.1.1) **Panel Architecture**: Explicitly defined panels (Chat List, Messages, Composer, etc.) with clear focus states (highlighted borders/titles).
- [ ] (2.1.2) **Focus Management**: Global cycling (Tab/Backtab) and directional navigation between panels.
- [ ] (2.1.3) **Key Hints Bar**: A persistent bottom bar displaying context-aware keybindings (e.g., "Enter: Select", "Tab: Next", "?: Help").
- [ ] (2.1.4) **Consistent Keybindings**: Standardize navigation (vim-style `j/k`, arrows), actions (Enter), and cancellation (Esc) across all contexts.
- [ ] (2.1.5) **Status Line**: Integrate connection status and other global info into the bottom or top bar, distinct from the key hints.
- [ ] (2.1.6) **Log Pane**: Make the log window a first-class citizen (toggleable panel or dedicated tab) rather than just an overlay, or improve its overlay behavior to match the new focus model.

### 2.2 Out of scope

- [ ] (2.2.1) Mouse interaction refinements (focus remains keyboard-centric).
- [ ] (2.2.2) Complete theming engine (colors will be hardcoded or basic config for now).
- [ ] (2.2.3) Changing underlying Telegram/LLM core logic.

### 2.3 Layout & Components

- **Chat List (Left)**: Scrollable list of chats. Focused state highlights the selected row and the pane border.
- **Message View (Right)**: Scrollable history. Focused state allows scrolling.
- **Composer (Bottom-Right or Bottom-Span)**: Input area. Focused state captures text input.
- **Key Hints (Bottom)**: Single line showing available keys for the _currently focused_ pane + global keys.
- **Status Bar (Top or Above Hints)**: Connection state, current user, etc.

### 2.4 Focus Model

- **Active Pane**: Only one pane is active at a time.
- **Visual Feedback**: Active pane has a different border color (e.g., Yellow/Green) and bold title. Inactive panes have dim borders.
- **Navigation**:
  - `Tab` / `Shift+Tab`: Cycle forward/backward through visible panes.
  - `h/j/k/l` or Arrows: Navigation _inside_ the focused pane (e.g., scroll list, move cursor).
  - Global Hotkeys:
    - `1`: Focus Chat List.
    - `2`: Focus Message View.
    - `3`: Focus Composer.
    - `?`: Toggle Help/Key bindings modal.

### 2.5 Key Hints Bar

- Dynamic content based on `UiState.focus`.
- Example (Chat List Focused): `j/k: Navigate | Enter: Select | /: Search | Tab: Messages`
- Example (Composer Focused): `Esc: Cancel | Ctrl+s: Send | Tab: Chat List`

## 3.0 Implementation plan

- [ ] (3.1.1) **State Update**: Refactor `UiState` to include an explicit `active_pane` enum (Chats, Messages, Composer, Logs, etc.).
- [ ] (3.1.2) **View Update**: Update `ui::view` functions to accept `active_pane` and render borders/styles accordingly.
- [ ] (3.1.3) **Component Refactor**: Ensure each "pane" is a distinct renderable component that knows how to render its own specific key hints.
- [ ] (3.1.4) **Input Handling**: Centralize input routing. The main loop delegates key events to the `active_pane` handler, or handles global keys (Tab, F-keys) itself.
- [ ] (3.1.5) **Key Hints Widget**: Create a new widget to render the bottom key hints bar.
- [ ] (3.1.6) **Wiring**: Connect the new state and view logic in `app/src/tui.rs` and `ui/src/lib.rs`.

## 4.0 Test plan

- [ ] (4.1.1) Snapshot tests for each focus state (check border styles).
- [ ] (4.1.2) Snapshot test for the key hints bar with different contexts.
- [ ] (4.1.3) Unit tests for state transitions (Tab cycling, specific focus keys).
